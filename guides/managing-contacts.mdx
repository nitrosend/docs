# Managing Contacts

Contacts are the people you send messages to. Each contact can have an email address, phone number, or both.

Keep evidence that recipients agreed to receive your marketing. Importing an
address or a **Subscribed** status does not itself prove permission. Preserve
opt-outs and suppressions when migrating a list; do not use an import or provider
switch to work around them. See [sender requirements](/guides/microsoft-delivery).

## Importing contacts

Go to **Contacts > Import** ([app.nitrosend.com/my/contacts/import](https://app.nitrosend.com/my/contacts/import)) to upload a CSV file. Map your columns to contact fields during import.

Imports run in the background and show live progress while rows are processed. You can leave the page and return to the progress tray later.

Imports start no flows unless you turn on **Start flows** under Destination lists. With it on, contacts the import creates enter the live New contact flows they match, and new list members enter that list's live Add to list flows. With it off, the import summary names any live flows the import didn't start. Unsubscribe and block imports can't start flows.

You can also connect Mailchimp from **Integrations** to migrate audiences and members directly into Nitrosend. Mailchimp contacts keep their source metadata, and only Mailchimp members with `subscribed` status are opted in for email in Nitrosend.

Editing a contact or importing it again preserves its existing subscription. Contacts who have unsubscribed or been suppressed remain protected when an integration syncs again.

You can also add contacts via the API:

```bash
curl -X POST https://api.nitrosend.com/v1/my/contacts \
  -H "Authorization: Bearer nskey_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane@example.com",
    "first_name": "Jane",
    "last_name": "Doe"
  }'
```

### Importing from another platform

Moving a list from another email tool takes more than one file, and the order matters. Import the files of people who unsubscribed, bounced or complained first, then your subscribed contacts. Anyone already unsubscribed or blocked stays that way when the contacts file arrives. [Migrating to Nitrosend](/guides/migrating-to-nitrosend) walks through the whole move and lists the files for each source.

### File roles

Every file you import has a role: what it says about the people in it. In the app you set it under **Email subscriptions** when you upload. Agents and the API set it in the import's `options`.

| The file holds | In the app | In `options` | What happens |
| --- | --- | --- | --- |
| Subscribed contacts | **Keep subscription choices** | nothing, or `file_role: "subscribed"` | New contacts are subscribed unless their row says otherwise. Unsubscribes in the file are always honored. |
| Unsubscribes | **Unsubscribe all from marketing** | `email_action: "unsubscribe"`, or `file_role: "unsubscribed"` | Every address is unsubscribed from marketing email |
| Hard bounces | **Block all email delivery** | `email_action: "block"`, or `file_role: "bounced"` | Every address is blocked from all email, recorded as a bounce when you use `file_role` |
| Spam complaints | **Block all email delivery** | `email_action: "block"`, or `file_role: "complained"` | Every address is blocked from all email, recorded as a complaint when you use `file_role` |

Send `email_action` or `file_role`, not both. These choices apply to this brand only and do not change SMS consent. Unsubscribe, block and suppression-role imports never start flows.

A positive value in a file never resubscribes someone who has opted out. If a contacts file has a status column, Nitrosend reads `subscribed`, `true`, `yes` and `1` as subscribed, and `unsubscribed`, `false`, `no`, `0` and `opted out` as not. If your old tool uses other words, such as `active` or `pending`, split the file by status and import each part with its own role.

### Recognized export files

Nitrosend recognizes some exports from their column headings, so a renamed file still works:

| Export | What Nitrosend does with it |
| --- | --- |
| Mailchimp unsubscribed audience export | Imports every row as unsubscribed |
| Mailchimp cleaned audience export | Imports every row as not subscribed and records a bounce |
| Klaviyo profile export | Maps the columns for you and reads each row's email consent. Only rows that say Subscribed are subscribed. |
| Klaviyo suppressed profiles export | Imports the rows as not subscribed, with the reason each row gives |
| Brevo contact export | Maps the columns for you and reads each row's subscription and blocklist status |
| Brevo blocklisted export | Imports the rows as not subscribed, with the reason each row gives |

A recognized export decides its own role. You cannot import a Mailchimp unsubscribed file as subscribed by choosing a different role, and a column mapping you send with a Klaviyo or Brevo export changes ordinary fields only: the email, phone and consent columns always come from the file. A phone number in a recognized export is never subscribed to SMS by default. Brevo files can use a comma or a semicolon as the separator.

For Klaviyo and Brevo exports, last open and last click dates and any sent, open and click counts are kept as imported engagement history on the contact. Importing the same export again replaces that history. It never adds to it.

Any other file imports with the mapping and role you give it.

### Import summary

When an import finishes, the app shows how the email addresses in the file came out:

| Count | Meaning |
| --- | --- |
| **Subscribed** | Addresses subscribed to email |
| **Unsubscribed** | Addresses unsubscribed from marketing email |
| **Blocked** | Addresses blocked from all email in this brand |

Compare these with the totals in your old tool before you send anything.

The import record in the API also carries `import_summary`, which counts the state each row's address ended in:

| Field | Meaning |
| --- | --- |
| `subscribed` | Rows whose address is subscribed |
| `not_subscribed` | Rows whose address is not subscribed and has no opt-out or delivery stop |
| `suppressed` | Rows whose address has opted out or has a delivery stop. Someone who had already opted out in Nitrosend counts here, whatever the file says. |
| `phone_only` | Rows with a phone number and no usable email address |
| `suppression_reasons` | Rows the file itself took out, by reason, such as `unsubscribe`, `hard_bounce` and `complaint` |

`success_rows` and `failed_rows` on the same record tell you how many rows were written and how many were not. Look into every failed row in an unsubscribe or bounce file: a row that failed is a person who can still be emailed.

## Contact lists

Organize contacts into lists for targeted sending. A contact can belong to multiple lists.

## Saved views

Use saved views to keep useful contact-table setups: search terms, filters, visible columns, and sort order. Saved views are helpful for day-to-day operations such as "recent imports", "VIPs with no recent clicks", or "contacts needing cleanup".

If the same rules should become an audience for campaigns or flow conditions, create a segment instead.

## Tags

Tags are free-form string labels (e.g. `vip`, `newsletter`, `trial`) you attach to contacts for segmentation and targeting. A contact can have any number of tags. Tags are stored as an array of strings under the reserved `tags` key on each contact's `data` object.

Any tag string you use with a contact — via the REST API, the MCP tool, or the dashboard — is created automatically on first use. You can manage tags programmatically in two ways:

### Via the REST API

Set the full list of tags on a contact by writing to `data.tags`. You can do this at creation time in the `POST /v1/my/contacts` body, or on an existing contact with `PATCH`:

```bash
curl -X PATCH https://api.nitrosend.com/v1/my/contacts/42 \
  -H "Authorization: Bearer nskey_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "data": { "tags": ["vip", "newsletter"] }
  }'
```

Filter contacts by a single tag with the `tag` query parameter:

```bash
curl -H "Authorization: Bearer nskey_live_..." \
  "https://api.nitrosend.com/v1/my/contacts?tag=vip"
```

<Warning>
  PATCHing the `data` field **replaces the entire `data` object**, not just the keys you send. If the contact has other custom fields (e.g. `data.plan`, `data.apollo`), sending `{ "data": { "tags": [...] } }` will wipe them.

  To add or remove tags safely via REST, `GET /v1/my/contacts/{id}` first, merge your changes into the existing `data` hash, then `PATCH` the full merged object back. For add/remove semantics across many contacts in one call — without the read-modify-write dance — use the MCP tool below.
</Warning>

### Via the MCP tool (agents)

When an AI agent is managing contacts on a user's behalf, use the `nitro_manage_audience` tool with the `bulk_tag` operation. It supports `add`, `remove`, and `set` semantics across many contacts in one call — no read-modify-write dance.

```json
{
  "operation": "bulk_tag",
  "params": {
    "contact_ids": [1, 2, 3],
    "tags": ["vip", "newsletter"],
    "tag_action": "add"
  }
}
```

- **`tag_action: "add"`** (default) — merges the given tags into each contact's existing tags, deduplicated.
- **`tag_action: "remove"`** — removes the given tags from each contact; leaves other tags untouched.
- **`tag_action: "set"`** — replaces the entire tag list on each contact with the given tags.

`contact_ids` is required — omit it and the call fails rather than silently tagging every contact in the brand. Pass `dry_run: true` alongside to preview the affected `contact_count` without persisting.

See [Example Workflows](/guides/mcp-examples#example-4-bulk-tag-contacts) for a full prompt-to-result walkthrough.

## Segments

Segments are dynamic groups defined by conditions (e.g., "subscribed in the last 30 days" or "opened an email this week"). Unlike lists, segments update automatically as contacts match or stop matching the criteria.

The segment builder supports profile, list membership, tag, custom-field, engagement, deliverability, and event-history filters. Tags are one of the available segment filters — use the `contact_tag` filter name with the `cont` (contains) predicate to build tag-based segments, e.g. `{ name: "contact_tag", predicate: "cont", value: "vip" }`.

## Contact activity

Open a contact to review their activity timeline. The timeline brings sends, opens, clicks, unsubscribes, bounces, complaints, list changes, and custom events together so you can understand recent behavior before sending again.
