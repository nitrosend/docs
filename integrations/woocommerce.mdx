# WooCommerce, WordPress and FunnelKit

Nitrosend does not have a WordPress plugin. You connect a WooCommerce or WordPress site by posting each new customer or signup to one Nitrosend endpoint. This page gives the exact request, then the steps for three ways to send it:

- [FunnelKit Automations](#funnelkit-automations), with its HTTP Request action
- [A WooCommerce webhook](#woocommerce-webhook), with a short code snippet
- [A pasted HTML form](#pasted-html-form), with no plugin and no script

Each person you send lands on a list. Joining a list starts that list's **Add to list** flows, so a new customer can enter a welcome sequence on their own. See [Trigger a welcome sequence](/guides/website-signup-forms#trigger-a-welcome-sequence).

Ask your agent: "Using Nitrosend, find my [list name] list and its ID, then tell me whether [test email] is on it and which custom fields it has."

## Before you start

You need two values from Nitrosend.

1. Go to **Contacts** and open the list new customers should join.
2. Edit the list and find the **Website signup form** panel.
3. Copy the **public key** from the snippet. It starts with `wpkey_live_`. If the brand has no key yet, click **Create website key**.
4. Copy the **list ID**. It is the number in `data-list-id="…"` in the same snippet.

Every key is also listed under **Settings**, then **API Keys**, in the **Public Key** row.

<Warning>
  Use the public key (`wpkey_live_…`) only. Never put a secret key (`nskey_live_…`) in a FunnelKit action, a WooCommerce webhook, a form or any web page. The endpoint on this page refuses every request that carries a secret key, and anyone who can read the page or the plugin settings could take the key.
</Warning>

### Leave allowed origins blank for server senders

FunnelKit and WooCommerce send from your web server, not from a visitor's browser, so their requests name no website origin. A key with **Allowed website origins** set refuses them with a `403`. Use a key with that field blank for FunnelKit and WooCommerce webhooks.

A pasted HTML form runs in the visitor's browser, so it works with allowed origins. If you use both, click **+ New key** in the panel and keep one key for each.

## The request

Send a `POST` to:

```
https://api.nitrosend.com/v1/public/contacts
```

The body can be form fields or JSON. Do not mix them: a body made of form fields must not carry a JSON `Content-Type` header.

| Field | Required | What it does |
| --- | --- | --- |
| `public_key` | Yes | Your public key. It must be in the body. A key in the URL is refused with a `400`. |
| `list_id` | Yes | The ID of the list to add the contact to. It must belong to the same brand as the key. |
| `email` | Yes | The contact's email address. |
| `first_name` | No | First name. |
| `last_name` | No | Last name. |
| `phone` | No | Phone number in international format, such as `+61400000000`. A number Nitrosend cannot read is skipped and the contact is still saved. |
| `source` | No | A label for where the contact came from, such as `store-au`. |
| `data` | No | Custom fields, nested under `data`. See below. |
| `redirect_url` | No | Form posts only. See [Pasted HTML form](#pasted-html-form). |

A sender that can set headers can send the key as `Authorization: Bearer wpkey_live_…` instead of the `public_key` field. When both are sent, the header is used.

### Custom fields

Custom fields go inside `data`. How you write that depends on the body format:

- Form fields: `data[city]=Sydney`
- JSON: `"data": { "city": "Sydney" }`

A few names inside `data` are reserved for Nitrosend's own integrations, such as `tags`, `shopify` and `stripe`. They are dropped.

<Warning>
  Do not send top-level fields named `company`, `website`, `url` or `honeypot`. They are spam traps for web forms. A request that fills one is discarded, and the response still says `{ "ok": true }`. Put those values under `data`, for example `data[company]`.
</Warning>

### What happens to the contact

- **A new email address** becomes a contact with the name, phone, source and custom fields you sent. It is subscribed to email and added to the list.
- **An email address the brand already has** is added to the list. Nothing else changes: its name, custom fields, source and subscription status stay as they were. An unsubscribed contact stays unsubscribed.

The response is `201` with `{ "ok": true }` in both cases.

## Consent

Nitrosend subscribes a new address as soon as it arrives. This endpoint does not read a consent field, so the decision is made on your site, before the request is sent.

Only send people who agreed to receive marketing email from you. Placing an order is not agreement. Set each method up so it fires on the opt-in, not on the purchase:

- **FunnelKit:** start the automation from a contact subscribing, as shown below.
- **WooCommerce webhook:** it fires for every new customer account and has no consent check. Use it only if creating an account on your store is itself the opt-in.
- **HTML form:** say on the form what people are signing up for.

## FunnelKit Automations

FunnelKit Automations can send data to any URL with its HTTP Request action. FunnelKit documents it in [Outgoing Webhooks](https://funnelkit.com/docs/autonami-2/webhooks/outgoing-webhooks/) and [Send nested JSON data using HTTP Request](https://funnelkit.com/docs/autonami-2/how-to/send-nested-json-data-to-any-source-using-http-request/).

1. In WordPress, open **FunnelKit Automations**, then **Automations**. Click **Create Automation**, choose **Start from scratch** and name it.
2. Select the event. To send only people who opted in, choose **Contact subscribes**. FunnelKit's [Checkout Consent](https://funnelkit.com/docs/autonami-2/settings/checkout-consent/) setting adds an opt-in checkbox to checkout: a buyer who checks it is marked Subscribed, and a buyer who does not is marked Unverified. FunnelKit's page also says that with the checkbox turned off, every customer is marked Subscribed, so keep it on.
3. Add an **Action** step. On the **Send Data** tab choose **HTTP Request** (shown as **Send Data To Any Source (HTTP Request)** in some versions) and click **Done**.
4. Set the method to **POST** and the URL to `https://api.nitrosend.com/v1/public/contacts`.
5. Under **Data**, add one row for each field in the table below.
6. Click **Send Now** to send a test, then save the action and turn the automation on.
7. [Check that the contact arrived](#check-it-worked) in Nitrosend. Do not rely on FunnelKit's own status.

The **Data** rows:

| Key | Value |
| --- | --- |
| `public_key` | `wpkey_live_…` (your public key) |
| `list_id` | `123` (your list ID) |
| `email` | `{{contact_email}}` |
| `first_name` | `{{contact_first_name}}` |
| `last_name` | `{{contact_last_name}}` |
| `phone` | `{{contact_phone}}` |
| `source` | `store-au` (any label you choose) |
| `data.city` | `{{contact_city}}` |
| `data.country` | `{{contact_country}}` |

If you start the automation from an order event instead, add a condition so only contacts whose status is Subscribed reach the HTTP Request step.

### Merge tags

FunnelKit merge tags use underscores, in double curly braces: `{{contact_email}}`, `{{contact_first_name}}`, `{{contact_city}}`. The full list is in FunnelKit's [Merge Tags](https://funnelkit.com/docs/autonami-2/merge-tags/) page. Copy each tag from the **Merge tags** button in the action instead of typing it.

Tags with a dot, such as `{{contact.email}}`, are not FunnelKit tags. FunnelKit sends them as plain text, and Nitrosend answers `422` because the text is not an email address.

### Custom fields in FunnelKit

FunnelKit's guide says to write nested keys with dot notation, so a custom field's key is `data.city`. After your test, open the contact in Nitrosend and confirm the field is there. If the contact arrived without it, your FunnelKit version sends keys as written: use `data[city]` as the key instead.

Do not add a `Content-Type` header unless FunnelKit's guide for your version tells you to. A JSON content type on a body made of form fields is refused with a `400`.

## WooCommerce webhook

WooCommerce can post new customer accounts without FunnelKit. Its built-in webhook sends a fixed JSON body, with no place for your public key or list ID, so this route needs a short code snippet to add them. Shoppers who check out as guests do not get a customer account and are not sent.

1. In WordPress, go to **WooCommerce**, then **Settings**, **Advanced**, **Webhooks**, and click **Add webhook**.
2. Set **Status** to **Active**, **Topic** to **Customer created** and **Delivery URL** to `https://api.nitrosend.com/v1/public/contacts`. Save.
3. Note the webhook's ID. It is the number after `edit-webhook=` in the address bar while you edit the webhook.
4. Add this snippet to a small plugin or a code snippets plugin. Replace the webhook ID, the key and the list ID.

```php
add_filter( 'woocommerce_webhook_payload', function ( $payload, $resource, $resource_id, $webhook_id ) {
    // 12 is the ID of the Nitrosend webhook.
    if ( 12 !== (int) $webhook_id || ! is_array( $payload ) ) {
        return $payload;
    }

    $payload['public_key'] = 'wpkey_live_…';
    $payload['list_id']    = 123;
    $payload['source']     = 'store-au';

    return $payload;
}, 10, 4 );
```

WooCommerce's customer payload already has `email`, `first_name` and `last_name` at the top level, which are the names Nitrosend reads. The other fields WooCommerce sends are ignored.

Two things to expect:

- When you first save an active webhook, WooCommerce pings the delivery URL. The ping carries no key, so Nitrosend answers `401` and WooCommerce shows an error with that response code. Deliveries for real customers carry the key from the snippet.
- WooCommerce turns a webhook off after repeated failed deliveries. If it shows as **Disabled**, fix the cause, set it back to **Active** and test again. See WooCommerce's [Webhooks](https://woocommerce.com/document/webhooks/) page.

Order topics, such as **Order created**, do not work with this endpoint. An order payload has no top-level `email`, and this endpoint does not record orders. See [What this does not cover](#what-this-does-not-cover).

## Pasted HTML form

For a newsletter signup on a WordPress page, paste a plain form into a **Custom HTML** block. It needs no plugin and no script, and it also works in any page builder that accepts form code.

```html
<form action="https://api.nitrosend.com/v1/public/contacts" method="post">
  <input type="hidden" name="public_key" value="wpkey_live_…">
  <input type="hidden" name="list_id" value="123">
  <input type="hidden" name="source" value="footer-form">
  <input type="hidden" name="redirect_url" value="https://yourdomain.com/thanks">

  <label>Email
    <input type="email" name="email" required>
  </label>
  <label>First name
    <input type="text" name="first_name">
  </label>
  <label>City
    <input type="text" name="data[city]">
  </label>

  <!-- Spam trap: leave hidden and empty, do not remove -->
  <input type="text" name="company" tabindex="-1" autocomplete="off"
         style="position:absolute;left:-9999px" aria-hidden="true">

  <button type="submit">Subscribe</button>
</form>
```

After a successful signup the visitor is sent to `redirect_url`, on two conditions:

- The key has **Allowed website origins** set, and the `redirect_url` page is on one of them.
- The page holding the form is on one of those origins too.

Without a `redirect_url` that meets them, the visitor sees the raw reply `{ "ok": true }`. A failed signup always shows the error and never redirects.

If you can add a script to the page, the drop-in form in [Website Signup Forms](/guides/website-signup-forms) shows a message in place and needs no thank-you page.

## Several stores, one account

Any number of stores can post to the same Nitrosend brand. Use the same public key on every store.

- Nitrosend matches on email address within a brand, so a shopper who buys from three stores is one contact.
- Each request adds the contact to the list in its `list_id`. A contact can be on many lists. Give each store its own list if you want to know which stores a shopper has used, or to start a different welcome flow for each store.
- `source` and custom fields are saved when the contact is first created, so they describe the first store that sent that shopper. Later requests from other stores add list memberships only.

## Check it worked

FunnelKit can show an automation run as completed whatever answer the request got. A completed run does not mean the contact arrived. Check in Nitrosend:

1. Send a test with an email address you own and have not used before.
2. In Nitrosend, go to **Contacts** and open the list. The contact appears within seconds.
3. Open the contact and confirm the name and custom fields.

To see the real response, send the same request from a terminal:

```bash
curl -i -X POST https://api.nitrosend.com/v1/public/contacts \
  -d "public_key=wpkey_live_…" \
  -d "list_id=123" \
  --data-urlencode "email=test@yourdomain.com" \
  --data-urlencode "first_name=Test" \
  --data-urlencode "data[city]=Sydney"
```

| Response | Meaning | Fix |
| --- | --- | --- |
| `201` `{ "ok": true }` | Accepted. | If no contact appears, look for a top-level `company`, `website`, `url` or `honeypot` field and move it under `data`. |
| `400` `public_key_in_query` | The key is in the URL. | Move it to a `public_key` body field. |
| `400` | The body does not match its content type. | Send form fields without a JSON `Content-Type`, or send real JSON. |
| `401` `invalid_key` | The key is missing, mistyped or a secret key. | Send the `wpkey_live_…` key in `public_key`. |
| `403` `origin_not_allowed` | The key has allowed origins and the request did not come from one. | Use a key with no allowed origins for FunnelKit and WooCommerce. |
| `404` `list_not_found` | The list is not in the key's brand. | Check the list ID and that the key is from the same brand. |
| `422` `invalid_request` | `email` or `list_id` is missing, or `email` is not an address. | Check the merge tag spelling and the field names. |
| `429` | Too many requests in a short time. | See below. |

The endpoint is rate limited per IP address and per key, and every request from one store comes from the same IP address. It is built for signups as they happen. To bring in customers you already have, [import them](/guides/managing-contacts) instead of replaying them through a webhook.

## What this does not cover

This endpoint creates contacts and adds them to lists. It does not record orders, revenue or any other event, and it cannot update a contact that already exists.

Flows that start from a purchase, order history, and revenue in reports need the [Events API](/integrations/events-api): `POST /v1/my/events`. That API accepts only a secret key, sent in an `Authorization` header, so it must be called from server code. Do not call it from a FunnelKit action, a WooCommerce webhook or a browser, and never paste the secret key into any of them.

On WordPress, server code means a small plugin on your own site. Keep the secret key out of the code, for example in `wp-config.php`:

```php
define( 'NITROSEND_API_KEY', 'nskey_live_…' );
```

Then send an event when an order is paid:

```php
add_action( 'woocommerce_payment_complete', function ( $order_id ) {
    $order = wc_get_order( $order_id );
    if ( ! $order || ! defined( 'NITROSEND_API_KEY' ) ) {
        return;
    }

    // Order IDs repeat across stores, so prefix them with the store's host.
    $store     = wp_parse_url( home_url(), PHP_URL_HOST );
    $order_ref = $store . '-' . $order->get_id();

    wp_remote_post( 'https://api.nitrosend.com/v1/my/events', array(
        'timeout' => 10,
        'headers' => array(
            'Authorization'   => 'Bearer ' . NITROSEND_API_KEY,
            'Content-Type'    => 'application/json',
            'Idempotency-Key' => $order_ref . '-placed',
        ),
        'body'    => wp_json_encode( array(
            'event'         => 'order_placed',
            'contact_email' => $order->get_billing_email(),
            'data'          => array(
                'order_id'     => $order_ref,
                'order_number' => $order->get_order_number(),
                'total'        => wc_format_decimal( $order->get_total(), 2 ),
                'currency'     => $order->get_currency(),
            ),
        ) ),
    ) );
} );
```

`woocommerce_payment_complete` runs when a payment gateway confirms payment. Orders paid offline, such as bank transfer or cash on delivery, do not trigger it.

The Events API page covers the full contract: event names, order fields, line items, refunds and how to use event data in a flow. Read [Send an event](/integrations/events-api#send-an-event) before you turn this on, because an event for an address Nitrosend has not seen creates a subscribed contact. If you only want buyers who opted in, check that in your code before you send the event.

A workflow tool that stores credentials on its own servers and can set request headers can call the Events API the same way.
